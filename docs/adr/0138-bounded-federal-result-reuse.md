# Reuse identical federal calculations in long projections

A 52-year default optimizer run exceeded 310 seconds. Profiling 20 identical annual evaluations measured 0.897 seconds, almost entirely in the federal package adapter; the household funding and settlement stages repeatedly ask for the same tax liability before any recognized input changes. The native zero-return/full-basis horizon and UI checks already established financial correctness, so performance work can retain the existing calculation path.

The federal adapter now uses a standard-library LRU cache of at most 4,096 successful raw calculations. Its key includes every record field/value, package year, requested output tuple and explicit insurance-income NIIT adjustment. Changed inputs still construct fresh validated Tax-Calculator Records, reset all read/calculated arrays and calculate under the existing process lock. Foreign-credit carriers and requested credit/AMT outputs therefore remain separate cache entries. No tax rules, rounding, payment reconciliation or recognition dates change.

Cached values are immutable tuples; each caller receives a new dictionary. A caller cannot contaminate another scenario by mutating its result. Cache entries stay in the local process and are never written to scenario files, logs or external services. The existing fixed package/policy version and process lifecycle bound their validity. The cache is a speed optimization, not a financial forecast or a new tax engine.

Independent package comparisons still cover different years and filing units. Concurrent miss checks clear the result cache before exercising the shared calculator, so cached hits cannot hide array-isolation failures. Additional checks cover reordered equivalent inputs, changed income/year, returned-dictionary mutation, requested output sets, foreign credits and policy-income NIIT. The full 624-month flat projection keeps all default safety targets and independently reconciles $851,999 in both training and held-out runs.

Validation: 29 affected package/reference/financial/UI checks pass with 98.21% measured combined coverage; the federal adapter is 100%. The final concurrent-miss/reference suite passes all 9 tests at 100% adapter coverage. The whole 1,223-file strict audit, Ruff, format and ty checks pass. Under the same cProfile instrumentation and warm-up, 20 identical annual calls fall from 0.897125 seconds to 0.004005 seconds, with 20 result-cache hits and one initial miss. This repeated-input measurement is not an end-to-end Monte Carlo speed claim.

The default complete search subsequently finished on the selected Mac in 309.357 seconds: two candidates with four common training paths each, followed by eight independent validation paths for the frozen winner, 624 months each. The cache recorded 31,603 hits and 9,965 misses. The earlier retirement candidate failed its cash-reserve target; the later candidate passed training and held-out constraints. The held-out success interval still has a lower bound of approximately 0.676, so eight successes do not establish a 95% population success rate. The uncached attempt was interrupted after 310 seconds, so there is no measured complete-run speed ratio. This establishes a completed long-horizon run; broader sampling and interactive throughput remain release considerations.
